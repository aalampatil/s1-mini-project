Problem model

Airports are vertices; airways are directed, weighted edges. Each edge carries four metrics computed from the scenario: time, fuel, CO₂e and a weather risk exposure. For the weighted-sum objective the planner minimises cost(e) = wt·time/reft + wf·fuel/reff + we·CO₂e/refe, where each ref is the network-average per-km value so the three terms are comparable. All costs are non-negative, so Dijkstra / A* are correct.

What changes an edge's weight?

  • Aircraft – cruise speed, burn rate, range (longer edges are removed) and take-off/landing fuel.
  • Jet stream – tail/head-wind component = jet speed(latitude) × sin(bearing); eastbound legs are faster.
  • Weather cells – average severity sampled along the great circle inflates flight time and fuel by 1 + penalty × severity.
  • Restricted airspace – an edge whose great circle enters a no-fly circle is deleted from the graph.
  • Airport congestion – taxi-out queue and arrival holding time depend on the airport's hub tier.
  • ATM sector load – busy airways add a delay factor 1 + 0.3·util⁴.
  • Long legs – carrying fuel for a long leg increases burn (1 + 0.4·(d/range)²), so a stop can save fuel but costs time.

Reading the results

  • On a graph this small all exact algorithms return the same cost; A* expands fewer vertices than Dijkstra. On large random graphs the heuristic is weak, so A* may expand fewer vertices yet not run faster – the experiment shows both effects.
  • Weighted-sum optimisation only finds "supported" trade-offs; the Pareto tab shows the whole front.
  • Fuel burn, CO₂e and flight time are modelled with simplified, illustrative formulas – this is an algorithms study, not an operational flight planner.
